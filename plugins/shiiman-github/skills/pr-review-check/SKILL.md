# Check PR Review

**自分の PR** に付いたレビューコメントを確認し、修正対応を実行します。

> **注意**: 他者の PR をレビューする場合は `pr-review` を使用してください。

## Help

`$ARGUMENTS` に `--help` が含まれる場合、以下を表示して終了:

```text
/shiiman-github:pr-review-check - レビュー指摘対応（PR 作成者向け）

概要:
  自分の PR に付いたレビューコメントを確認し、修正対応を実行する。
  既定は確認のみ。「修正して」と伝えると修正まで実行する。

使用方法:
  /shiiman-github:pr-review-check [PR番号]

オプション:
  --help  このヘルプを表示

実行モードの伝え方（フラグの代わり）:
  指定なし              → レビュー指摘の確認のみ（修正・投稿はしない）
  「修正して」「対応して」 → 指摘を修正して検証。コミット・push・返信はそれぞれ依頼済みの場合だけ実行

例:
  /shiiman-github:pr-review-check        # 現在のブランチの PR のレビューを確認
  /shiiman-github:pr-review-check 123    # PR #123 のレビューを確認
  「レビュー指摘を修正して」              # 指摘を修正して対応
```

## 起動時の自動判断（フラグの代わり）

引数・発話から実行モードを判定する。明示がなければ「確認のみ」とする（安全側）。

| モード   | 条件                             | 動作                                               |
| -------- | -------------------------------- | -------------------------------------------------- |
| 確認のみ | 既定                             | 指摘事項を分類して表示するだけ。修正・投稿はしない |
| 修正     | 「修正して」「対応して」等の発話 | 指摘を修正・検証し、許可された後続操作だけを実行   |

修正だけの依頼はローカル修正と検証で完了する。コミット・push・返信投稿は、それぞれ明示的な依頼または親ワークフローの許可がある場合だけ実行し、同じ操作の許可を取り直さない。返信投稿の許可は修正や PR 更新の依頼だけから推測しない。

## ワークフロー

### ステップ 1: PR 番号の特定

PR 番号が指定されていない場合、現在のブランチの PR を検出:

```bash
gh pr view --json number,title,url
```

### ステップ 2: レビューコメントの取得

```bash
# PR のレビューコメント取得
gh api repos/{owner}/{repo}/pulls/{pr番号}/comments

# PR レビュー取得
gh pr view {pr番号} --json reviews
```

### ステップ 3: 指摘事項の分類と表示

| プレフィックス | 種別     | 対応                                       |
| -------------- | -------- | ------------------------------------------ |
| must.          | 修正必須 | 修正の必要性を検証し、許可範囲内で対応     |
| imo.           | 改善提案 | 採否を検討し、許可範囲内で対応             |
| nits.          | 軽微     | 修正を検討し、許可範囲内で対応             |
| q.             | 質問     | 回答案を準備し、投稿許可がある場合だけ返信 |

**表示形式**:

```
=== PR #{pr番号}: {タイトル} ===

【must.】修正必須 (N件)
1. [{ファイル}:{行}] {コメント内容}
   comment_id: {id}

【imo.】改善提案 (N件)
...

「修正して」と伝えると、指摘の修正まで実行できます。
```

確認のみモード（既定）の場合はここで終了する。

### ステップ 4: 修正の実行（修正モードと判定した場合）

各指摘事項について:

1. 対象ファイルを Read で読み込む
2. 指摘内容を理解して修正方針を決定
3. Edit で修正を実行
4. 修正内容を記録（返信用）

### ステップ 5: 許可されたコミット・push

修正内容を検証し、コミットが依頼済みなら対象パス・hunk だけをコミットする。コミットだけの依頼ではそこで終了する。push または PR 更新まで依頼済みの場合だけ、必要な通常の feature branch push を行う。無関係なステージ済みの変更や未ステージの変更を保護する。許可がない場合はローカル修正と検証結果の報告で終了し、任意の後続操作を追加で質問しない。具体的な範囲変更や危険な操作が必要な場合だけ確認する。force-push やデフォルトブランチへの push に許可を広げない。

### ステップ 6: レビューコメントへの返信（重要）

**返信投稿が明示的に依頼されている場合だけ、各コメントへの対応内容を確認して投稿する。** 許可済みの返信は再確認せず、未実行の修正を実行済みと記載しない。

```bash
gh api repos/{owner}/{repo}/pulls/{pr番号}/comments/{comment_id}/replies \
  -X POST \
  -f body="修正しました。{修正内容の説明}"
```

**返信メッセージのテンプレート**:

| 対応種別     | 返信メッセージ                                                              |
| ------------ | --------------------------------------------------------------------------- |
| コード修正   | `修正しました。{具体的な修正内容}`                                          |
| 提案採用     | `ご提案ありがとうございます。採用しました。`                                |
| 質問への回答 | `{質問への回答}`                                                            |
| 対応見送り   | `ご指摘ありがとうございます。{理由} のため、今回は見送りとさせてください。` |

### ステップ 7: 結果報告

```
## レビュー指摘への対応を完了しました

### 修正内容
| 指摘 | ファイル | 対応 | 返信 |
|------|----------|------|------|
| must. {内容} | {file}:{line} | {実際の修正状況} | {返信済み・未投稿} |
| imo. {内容} | {file}:{line} | {実際の修正状況} | {返信済み・未投稿} |

### コミット
- ハッシュ: {実際にコミットした場合だけ記載}
- プッシュ: {実際の結果・未実行}

再レビューをお願いしてください。
```

## 返信 API の詳細

### コメントへの返信

```bash
# comment_id は gh api で取得したレビューコメントの id
gh api repos/{owner}/{repo}/pulls/{pr番号}/comments/{comment_id}/replies \
  -X POST \
  -f body="修正しました。"
```

### レビュー全体への返信（オプション）

```bash
gh pr comment {pr番号} --body "レビューありがとうございます。全ての指摘に対応しました。"
```

## 重要な注意事項

- ✅ 修正したら**必ず**コメントに返信する
- ✅ 返信には具体的な修正内容を記載する
- ✅ 質問には丁寧に回答する
- ✅ 対応見送りの場合も理由を説明する
- ❌ 指摘を無視しない
- ❌ 返信せずにプッシュだけしない
